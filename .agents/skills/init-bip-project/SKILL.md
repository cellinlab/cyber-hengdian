# 初始化 BIP 项目

从仓库根目录读取 `AGENTS.md`、`template.config.json`、`README.md` 和 `specs/VISION.md`；先查看 Git 状态，保护现有修改。

如果 `stage` 已为 `project`，先判断用户是在扩展已有项目还是明确重建；扩展按现有规格开发，不能覆盖成模板初始状态。

## 从想法到最小交付

从请求提取用户、用途和最小成功条件。只有缺口会改变核心方向或授权时才追问；可逆技术选择说明假设后继续。不要为了填满标题发明需求、性能数字或上线状态。

填写 `specs/VISION.md` 中对当前项目有用的部分：目标、最小范围、暂不做、验证方式，以及实际选用的技术与运行方式。尚未决定的内容明确标注。选择适合交付的技术，不自动安装一整套框架。

实现用户本轮要求的最小可运行版本。将 README `bip:project` 区替换为该项目的名称、用途、当前功能、安装运行、验证、部署状态及限制。配置的 `project.name` 与 `project.summary` 同步实际内容，`stage` 设为 `project`。

## 作者边界

默认 `owner: cell`：保留 `bip:creator` 区、`cell` 配置、联系与赞助图片。用户明确是其他作者时设 `owner: custom` 并替换作者信息；缺失联系方式可省略，不使用 Cell 的收款或联系码冒充新作者。保留 README 区域标记和 MIT 原声明。未经要求不更换二维码、不写个人私密信息。

## 验证与交付

运行 `python3 scripts/check_template.py --project`，处理残留占位符、坏的本地链接或作者区误改。再运行所建项目适用的验证；检查脚本不等于应用测试。若 Python 不可用，人工核对相同边界并报告未运行原因。

只有当前项目确有需要时才新增 BIP 开发记录，记录有价值的决定、实验与结果。交付说明可运行产物、验证证据和未解决项；提交、部署和发布按本轮授权，不从初始化请求自动推导。
