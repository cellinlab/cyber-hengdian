# 赛博横店 / Cyber Hengdian

## 从目标推导

创作的瓶颈不仅是生成画面，还包括表达空间关系、调度时间、镜头意图以及修改后保留哪些决定。一次创作应当成为下次创作的材料；不同工具和 Agent 应共同操作这份材料。

基本单位是可继续编辑的工程。场景、演员、动作和镜头有稳定身份；画面是工程在某个时刻、某台摄影机下的求值结果。自然语言负责提出修改，确定性工具负责执行、保存与验证。人可以随时直接修改。

## 首版产品契约

本地优先的导演台、开放工程格式、原子操作服务、CLI 与 stdio MCP，共用同一个核心。三个内置片场和九个镜头配方用于证明可复用性。支持自包含 GLB、本地文件持久化、冲突检测、撤销重做、关键帧、稳定跟拍、注释、按帧输出及可恢复的制作包。

完整生成适配层分阶段实现。首版无密钥即可摆场、拍摄并导出输入；不模拟云端生成成功，不内置大模型聊天框。外部 Agent 是独立入口。

## 非目标

首版不承担完整 NLE、任意骨骼重定向、物理求解、多人云协作、付费资产市场和跨渲染器像素一致性。MCP 协议测试不能代替真实宿主中的模型行为测试。

## 成功条件

- 人和 API 使用同一操作核心；过期修改被拒绝，已保存工程重启不丢失。
- 删除前面的对象不改变跟拍身份；三轴姿态和动画保存后往返一致。
- 同一帧的画面、深度和对象 ID 通道由同一场景状态生成。
- 工程包可在另一工作目录导入，包含所用 GLB 和来源信息。
- 三个片场分别支持人物对白、产品演示和室外运动；镜头配方可替换主体。
- 网页实际操作、HTTP 服务与 MCP 协议均有测试，报告范围不夸大。

## 技术与运行

TypeScript 核心，Zod 验证，Three.js 渲染，React 工作台。Node 服务作为唯一写入者，快照与历史一起原子写盘；本地 HTTP + SSE，MCP/CLI 为客户端。Vite 构建前端，Playwright 和 FFmpeg 逐帧导出。

`npm install` 后 `npm run dev`；默认仅监听 127.0.0.1:4317。`npm run check` 验证核心与构建，`npm run test:e2e` 验证真实浏览器流程。详情以 README 和测试结果为准。当前只交付本地工程，不自动创建远端仓库或部署。
