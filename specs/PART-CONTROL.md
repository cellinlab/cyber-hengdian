# 部件结构控制与外观参考

状态：首版已实现并验证。部件标记、可见表面遮罩、外观绑定、CLI/MCP 与拍摄包恢复见 [使用说明](../docs/PARTS.md)。跨对象控制组、自动面片分割与下游生成对比仍是后续能力。日期：2026-10-13。来自创作者提供的 [讨论链接](https://x.com/cellinlab/status/2109469155724603458) 与本轮粘贴的工作流建议：将车辆分为2–3个Part，分别导出遮罩，再提供外观参考。该X页面本次网页读取失败；本文采用用户提供的摘录，不将其当作已独立验证的效果证据。名称为 Wondful 的插件没有定位到可确认的官方仓库，未采用其代码或声称验证其开源许可。

## 决策

建议做，优先于单纯继续堆模型数量。它补足基础设施中“这一块是什么、哪里不能混在一起、外观参考作用于哪里”的表达能力。产品名称建议使用“部件与参考”，以创作对象为入口；Object ID、Part ID、PNG序列等细节放在高级导出选项。

当前 `Stage.render('id')` 会沿 Mesh 的父层级找到根 Entity，并为整个 Entity 的子网格赋同一ID。导出 manifest 记录 Entity → 数值/颜色映射。对象拆为几个独立实体时，现有通道可区分这些实体；单个GLB内部的多个部件目前不能分别控制。数值ID由导出快照的实体顺序产生，因此不能把像素颜色当成跨工程的永久身份。

## 首版交互

1. 选中车辆 → “部件与参考” → 从模型节点树选网格，归入“车头”“车厢”“车轮”。默认建议2–3个语义部件，但不设置这个数量为格式上限。
2. 点击部件，在正常画面高亮检查；切换“彩色部件预览 / 当前部件黑白遮罩”。允许多个Mesh归入一个部件，也允许不同实体组成一个控制组。
3. 为整个车辆或单独部件绑定外观参考图，填写简短约束，例如车厢保持长方体，车头红色，车厢银灰色。能明确区分“空间/形状参考”和“外观/材质参考”。
4. 导出时选择需要的部件，输出与RGB视频相同镜头、分辨率、时间戳的PNG遮罩序列、代表帧、映射manifest，以及原始外观参考与用途说明。
5. 选择下游工作流时明确显示其接受哪些输入。支持区域遮罩的工作流才传结构遮罩；仅支持图/视频参考的工具可用已转译的关键帧和运镜视频。没有能力支持时，不在界面声称“结构锁定已启用”。

## 数据与运行规则

- 稳定的 `partId` 与人可读名称分离，归属 Entity 或显式控制组。资产实例复制时新建实例身份；资产内的语义部件定义可复用。
- 内置模型由作者声明部件。GLB优先使用节点索引/路径、primitive或材质分组，并以资产内容哈希绑定拓扑版本；不能只按可能重复的节点名称定位。未分组的单Mesh不承诺自动语义分割，可要求在Blender拆分或后续增加面片选择工具。
- 人物部件与骨骼关节不是同一概念。头、上衣、手等遮罩标签追随实际变形网格；关节坐标本身不等于表面分区。
- 映射必须按导出快照生成并保存；跨帧同一部件使用同一编码。增加、删除、排序或隐藏其他对象不能导致语义对应丢失。
- 默认输出**可见表面遮罩**，保持真实遮挡：车头被前景遮住时，相应像素应为黑色。不是自动补全被挡住轮廓的 amodal mask。
- 原始ID使用无损整数编码，不经过色调映射、有损JPEG或H.264。黑白单部件遮罩可以提供独立的边缘覆盖版本；不能通过混合ID颜色制造不存在的部件编号。
- 玻璃、透明叠层、景深和运动模糊需要另设覆盖语义。本项目现有控制通道按不透明几何处理，不能冒称 Cryptomatte。真正支持这些场景时可评估标准化EXR方案。
- 外观参考以内容哈希保存并随包携带，记录来源、用途和对应部件；未经确认的远程短链和秘密不得进入持久包。
- UI / CLI / MCP使用同一套schema与版本化事务。新增部件后，Agent能查询、命名、绑定参考、预览遮罩和导出，而非只能靠点击界面完成。

## 首个验证案例

做一台原创三部件小卡车：车头、车厢、车轮；安排前侧绕行机位、车头与车厢互相遮挡以及前景路灯遮挡。先验证通道正确，再检验生成效果。

确定性验收：稳定身份、不同部件无串色、遮挡正确、每帧时间对齐、修改颜色不改变遮罩、复制/撤销/导入恢复、单GLB多节点分组、透明边界声明准确。至少同时看彩色ID和每个部件的黑白图，不能只检查文件数量。

生成侧实验比较：A只有白模视频；B白模视频+外观图；C在实际支持遮罩/区域控制的工作流中增加Part ID。模型、提示词和随机种子在可控范围内保持一致；模型不同就不能把差异全部归因于遮罩。检查车头/车厢边界、比例、连接关系、颜色串位和跨帧稳定性。输出遮罩成功不等于减少粘连已得到证明。新的付费生成须遵循单独明确的预算，过去案例预算不自动延续。

## 来源及可复用上限

- [Blender ID Mask 官方文档](https://docs.blender.org/manual/en/3.2/compositing/types/converter/id_mask.html)：对象或材质索引可生成遮罩；这里只采用基础机制，不把旧版页面当作当前UI说明。
- [Psyop Cryptomatte 官方仓库与规范](https://github.com/Psyop/Cryptomatte)：开放ID matte标准，处理运动模糊、透明与景深等覆盖信息。它是合成与标识基础，不承诺生成模型会服从结构。
- [Blender官方扩展目录的 CryptoMatte ID Color](https://extensions.blender.org/add-ons/cryptomatte-id-color/)：可确认存在对象/材质ID工作流的另一实例；它不是已确认的Wondful，同样不能据此替代插件身份或许可核验。
