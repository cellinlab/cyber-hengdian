# 架构与交互决策

## 不变量

1. 工程不依赖聊天记录、DOM 或特定 Agent 的记忆。
2. 资源引用、对象身份、镜头身份相互独立；删除操作维护引用完整性。
3. 编辑提交必须声明 baseRevision；一次命令批次全部成功或全部失败。
4. 运行器以明确时间求值，不累加上次帧的副作用。
5. 导出固定工程快照，不受导出期间的编辑影响。
6. 文件写入失败不能在内存中报告成功；历史与项目共同持久化。
7. 未完成、失败、取消、完成是不同任务状态。

## 分层

- core：带版本 schema、命令、引用检查、动画求值、包目录。无 React、HTTP、Three.js 依赖。
- runtime：把求值状态映射到 Three.js。可替换，不拥有工程真源。
- server：唯一写入者，原子存盘、历史、事件通知、资产仓库、导出任务。
- director：选择、拖动、属性、关键帧、镜头表、批注；仅发送公开命令。
- CLI / MCP：连接运行中的同一服务，返回结构化事实，不维护第二份工程。

本版采用单个本地工作空间。多个独立工作空间可用不同目录和端口启动。不把本地服务直接当作公开多租户服务。

## 数据

Project → Entities + Shots + Notes。对象有稳定 ID、完整四元数、位置与缩放；每个镜头持有自己的对象关键帧覆盖。镜头从共享片场起拍，因此一个镜头的走位不会污染其他镜头。Camera 使用起止位置、起止目标、FOV、稳定目标 ID。帧率和时间边界显式定义。

资源包分开描述片场、对象与镜头配方。模型使用内容哈希寻址，自包含 GLB 禁止外部网络资源；工程引用资产，不拷贝进每个镜头。内置程序化布景也是具版本号的资源包，声明来源和许可。

## 操作与并发

客户端在读取 revision 后提交 requestId + baseRevision + operations。服务验证整批，提交新版本并广播 SSE。相同 requestId 和相同内容返回原结果；相同 ID 不同内容拒绝。409 提示重新读取并重新判断，不自动用旧状态覆盖。变换拖动期间保持本地预览；鼠标松开才提交，仍检查拖动开始时的版本。

## 交互设计

视觉主张：像一个安静的实景摄影棚，深墨灰工具区、暖色片场和单一荧光黄绿色操作色。画面是主角，参数服从拍摄任务。

内容组织：顶部工程与保存状态；左侧片场资源/场内对象；中央自由布置与摄影机视角；右侧根据选择展示对象或镜头；底部按镜头组织时间与关键帧。导出、接入说明、批注作为按需面板，不永久挤占画面。

交互主张：切换镜头立即看见构图；时间拖动即时求值；控件反馈短而明确。尊重 reduced-motion。桌面完整操作，小屏折叠资源和检查器，不把四列硬挤在手机上。

从零开始：选择片场 → 用已有镜头获得第一张画面 → 加入/替换主体 → 直接布置 → 设置起止动作与镜头 → 播放检查 → 导出拍摄包。进入已有工程则恢复最后保存数据，镜头/选择等个人视图状态可独立保存。

## 格式与扩展

首版只承诺自身 v1 schema。未知版本明确拒绝。未来在显式迁移函数中升级，不静默猜测。后续插件面：资源目录、渲染器、生成服务、剪辑交换。保持接口小而真实，当前没有跑通的后端不注册为可用。

## 验证边界

协议与引擎测试证明操作正确；三类真实浏览器场景证明编辑可用；逐帧输出测试证明帧数和通道对齐。外部模型生成质量、不同宿主的能力以及跨设备渲染仍须分别实测。
