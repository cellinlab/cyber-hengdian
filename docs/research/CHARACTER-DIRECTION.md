# 人物导演能力：姿态、动作与可复用骨架

调研日期：2026-10-13。范围：官方产品说明和手册；本轮没有购买、登录试用或导入竞品模型。下文把官方可核验能力、项目已实现能力、后续建议分开。官方说明能证明产品宣称，不能替代我们对其动作质量或稳定性的实测。

## 1. 目标与拆分

人物导演需要回答四件事：谁在什么位置、身体如何表达、动作在何时发生、镜头能否看清。将这些问题全部压进一句视频提示词，会丢失可检查的中间状态。赛博横店应保留可编辑数据、确定性预览和可导出的控制依据。

采用三类独立数据：

- **Pose（姿态）**：关节局部旋转和根部偏移。可以保存、交换、精确编辑。
- **Action（动作）**：时间到姿态的映射。可以是参数化周期动作或显式姿态关键帧。
- **Locomotion（走位）**：人物实体在场景中的世界位置和朝向轨迹。走位不自动意味着行走，传送、滑行和角色被移动也应能表达。

可复用的基础设施是稳定的关节语义与时间规则。更多预设、不同模型渲染器、AI harness、Blender 桥接都可以围绕这个协议增长。

## 3. 本轮已实现的数据与运行契约

源码位置：`src/core/actor.ts`、`src/runtime/actor.ts`。这是原创程序化预演人物：有脸部朝向线索、手脚和可弯曲关节，不是写实人体、蒙皮角色、动捕或全身 IK。

```ts
Pose = {
  rootOffset: [x, y, z], // 米；各轴 -3..3；默认 [0,0,0]
  joints: { [jointId]: [xDegrees, yDegrees, zDegrees] }
}
Actor = {
  pose: Pose,
  action: 'none' | 'walk' | 'run' | 'wave' | 'talk' | 'idle',
  speed: number, // 0..4；默认 1；周期频率倍率
  phase: number  // 0..1；默认 0；周期相位
}
PoseKey = { time: number, pose: Pose } // 秒
```

`actorSchema.parse({})` 会生成完整中立姿态。省略的关节归零；未知关节、非有限数字、超限角度由 schema 拒绝。`actorTupleSchemas` 对外提供 tuple 实例，供 MCP JSON Schema 使用数值数组表示；宿主兼容转换不应移除服务端的逐轴限位校验。

### 坐标与自由度

模型 +Y 向上、+Z 朝前。局部欧拉旋转顺序为 XYZ，数据单位为度。左/右属于人物自身。根部站立高度 0.94 米，左右大腿、小腿各 0.43 米。实体 transform 管世界放置，`rootOffset` 在实体空间内调整骨盆高度；坐、跪不能只改腿角而保持骨盆站立高度。

| 关节 ID | 用途 / 可动范围说明 |
| --- | --- |
| `root` | 整体局部朝向，三轴 ±180°，关键帧使用最短角度路径 |
| `pelvis` | 骨盆前后、扭转、侧倾，范围见 `jointDefinitions` |
| `spine` | 躯干俯仰、扭转、侧倾 |
| `neck`, `head` | 颈和头独立旋转，可表达注视方向；眼球当前没有独立控制 |
| `leftShoulder`, `rightShoulder` | 三轴肩关节；手臂初始向下，负 X 向前举 |
| `leftElbow`, `rightElbow` | 负 X 屈肘，Y 提供前臂转向的小型预演近似，Z 仅小范围；不是解剖医学模型 |
| `leftWrist`, `rightWrist` | 三轴手腕；手与拇指为固定几何，未实现逐指骨架 |
| `leftHip`, `rightHip` | 三轴髋；负 X 向前抬腿 |
| `leftKnee`, `rightKnee` | X 为 0..155°，Y/Z 锁定；不允许膝反折 |
| `leftAnkle`, `rightAnkle` | 三轴脚踝，保持独立脚掌方向 |

限位是适用于此预演 rig 的工程约束，不是普适人体关节测量值。外部角色的坐标基、比例和限位必须另外声明，不能只用同名字符串硬套。

原创建姿预设：自然站立 `stand`、坐姿 `sit`、单膝跪地 `kneel`、蹲伏 `crouch`、向前伸手 `reach`、侧向指示 `point`、举手招呼 `wave`、奔跑起势 `run`。预设为纯数据，随仓库 MIT 授权；不来自竞品姿态文件或外部动作库。

### 时间求值规则

1. `sampleActor(actor, time, poseKeys?)` 为纯函数。向前播放、向后跳转、随机取帧都只取决于输入；不得累计上一次的关节变换。
2. 没有 poseKeys 时，选中的程序动作在静态 `actor.pose` 上叠加局部角度，并限制在合法范围。`speed=0` 冻结当前相位；`none` 返回静态姿态。需要标准动作时，从 `stand` 起步；对已经举手的预设再次叠加 `wave` 可能到达关节限位。
3. 有非空 poseKeys 时，**整条显式姿态轨优先于程序动作**。首关键帧之前保持首姿态，末关键帧之后保持末姿态，中间线性插值全部关节角度和根偏移；root 使用最短角路径。关键帧必须时间严格递增。
4. 当前不是多轨动作混合系统，没有关节 mask、动作权重、动作段自动过渡或接触求解。不要把整姿态覆盖误写成高级 animation blending。
5. world transform 走位与关节动作独立。只有走位而 `action=none` 时，人物可以保持静态姿态移动；有 `walk` 而没有走位则原地演示行走。单镜需要动作时，可以把 `sampleActor` 烘焙成该镜头的 poseKeys，避免改变其他镜头。
6. 原有未设置 `entity.actor` 的人物仍使用原渲染约定。新增 articulated actor 的数据明确启用新 rig，不根据模型外观猜测兼容性。

程序 `walk` / `run` 是周期性摆腿屈膝的预演动作，没有步距与世界速度耦合、足底锁定、地形适配、重心平衡或碰撞。它能表达动作与姿态节奏，不能当作运动捕捉质量或物理真实行走验收。站立和坐姿的标准预设脚底在 y=0；蹲伏及单膝跪地预设也有无地面穿透回归。任意用户姿态组合不保证接地。

## 4. 下一步的交互和实现建议（尚未实现）

### 从导演意图进入，保留精确编辑

选择人物后先给“站 / 坐 / 跪 / 蹲 / 指向 / 招手”图示；再显示“身体朝向、注视、左右手、左右脚”分组。精确关节数字保持可见且可复制，供高级用户与 Agent 使用。修改前后展示同一机位，用户可以直接确认手是否被身体遮住、动作是否出画。角色朝向与相机视线不能混成同一个旋转控件。

自然语言“面向门，左手扶桌，右手指向对面的人”应转成三组可验证约束：根朝向、左手接触目标、右手方向。Agent 提交候选值后必须取实际预览；只有工具请求成功不足以证明导演意图成立。目标无法触及时明确反馈，不偷偷缩放手臂。

### 两段 IK 与接触应优先于堆积动作数量

建议先为肩—肘—腕和髋—膝—踝建立解析两段 IK：输入目标点、弯曲平面、影响权重与是否允许拉伸。坐标统一转换到角色局部空间，限制目标距离，保留确定性。接触声明可用实体 ID + 局部锚点 + 起止时间 + 接触部位，并在目标物体移动时重新求值。

求值顺序建议为：基础姿态 → 动作/关键帧 → 可选局部混合 → IK 接触 → 关节限位与无法到达报告 → 世界变换。足底接触需要“何时锁住、何时释放”，否则落脚会抖动或瞬移。完整全身 IK、平衡、物理碰撞需要单独预算和真实案例，不能用一组滑块命名替代。

### 动作复用与重定向

后续动作资产建议声明 `rigVersion`、单位、朝向、绑定姿态、关节 mask、duration、loop、根运动模式、接触标记、来源许可。先支持本 rig 的姿态 JSON 和动作 JSON，然后设计 GLB/Blender bridge。

重定向至少需要：来源骨名到语义关节的映射、局部坐标基、静止旋转校正、身高/骨长比例、根运动处理、缺失关节报告。不要默认外部 glTF 动画能驱动当前 Group 层次；真正蒙皮模型还需要 bones、inverse bind matrices 与 animation tracks 的映射。初版可让外部原生动画按原骨架播放，待验证映射后再加入跨角色重定向。

混合先从上/下半身 mask 与两动作权重开始，并明确 additive / replace。旋转叠加转为 quaternion 后再求值，UI 可以继续展示角度；同时规定混合后的限位和接触冲突处理。当前线性角度关键帧是简单可预测的起点，不应因此锁死以后协议。

## 5. 验证要求

当前 `tests/actor.test.ts` 覆盖完整默认值、非法关节/角度拒绝、预设有效性、无状态取帧、不修改源数据、动作关节限位、速度冻结、姿态轨覆盖、root 最短角插值、肘部子链移动、站坐脚底与跪蹲无穿透，以及 entity 世界位置保留。

这些测试只证明数据和变换契约。视觉验收还应查看站/坐/跪/蹲/指向/招手的正面与侧面，以及移动镜头的起/中/末帧和完整播放。检查手脚接地、前后方向、关节连接、主体遮挡、动作停止和导出一致性；不得用 schema 通过或 MP4 存在替代画面质量结论。
